.. _bk_securify_efuse:

EFUSE
=====================

:link_to_translation:`en:[English]`

概述
------------------------

EFUSE (Electrically Programming Efuse) 用于配置 BK7236N 中与安全相关的特性，只能由 0 配置成 1，无法由 1 配置成 0。

BK7236N EFUSE 共有 4x8 共 32 Bits, 在安全启动使能前，可以通过 :ref:`BKFIL<bk_tool_bkfil>` 配置，详情请参考 :ref:`EFUSE 配置 <bk_config_otp_efuse>`。

.. _efuse_bit0:

BIT(0) - secure boot
+++++++++++++++++++++++++++++++++++++++++++++++

BIT(0) 用于控制是否强制使能安全启动：

 - 0 - 不强制使能安全启动。
 - 1 - 强制使能安全启动。

当 :ref:`BIT(0)<efuse_bit0>` 配置为 0 时，表示 EFUSE 未强制使能安全启动，此时安全启动流程受以下条件控制：

 - 若未设置安全启动标志(BK.SB)，BL2 不做验签，仅做 IMAGE 完整性校验。
 - 若设置了安全启动标志(BK.SB)，BL2 则会执行完整的安全启动验签流程。

当 :ref:`BIT(0)<efuse_bit0>` 配置为 1 时，表示由 EFUSE 强制使能安全启动，此时 BL1 会执行完整验签流程。

.. note::

  是否因 OTP 中缺少 :ref:`BL1 ROTPK HASH<otp_bl1_rotpk_hash>` 而启动失败，取决于芯片当前的生命周期 (LCS)：

   - 当 LCS 处于 CM/DM（开发阶段）时，即使已使能安全启动，若 OTP 中未配置公钥 HASH，BL1 会跳过验签（打印 "Secure Boot is bypassed"）并继续启动。
   - 当 LCS 处于 DD/DR（部署/量产阶段）时，OTP 中必须配置公钥 HASH，否则启动失败；此时也无法再关闭安全启动。

.. note::

  一旦使能安全启动，将无法再通过 BKFIL 下载配置！因此应在完成所有其他 OTP/EFUSE 配置后，最后再使能 BIT(3)。
  使用 :ref:`配置脚本 <bk_config_otp_efuse_scripts>` 部署时，请确保所有需要配置的 OTP/EFUSE 项都已包含在配置脚本中。

.. _efuse_bit1:

BIT(1) - security boot debug mode
+++++++++++++++++++++++++++++++++++++++++++++++

BL1 定义了两级调试信息来供用户定位问题：

 - :ref:`BIT(1)<efuse_bit1>` - 控制普通调试信息。
 - :ref:`BIT(7)<efuse_bit7>` - 控制严重错误。

普通调试信息除了错误之外，还包括一些流程性的日志打印。严重错误通常是指会导致 BL1 启动失败的错误，当前 BL1 支持下述严重错误:

+-----------+---------------------------------------------------+
| 错误码    | 含义                                              |
+===========+===================================================+
| 0x1       | 读 EFUSE 出错 1                                   |
+-----------+---------------------------------------------------+
| 0x2       | 读 EFUSE 出错 2                                   |
+-----------+---------------------------------------------------+
| 0x3       | 读 FLASH 出错 1                                   |
+-----------+---------------------------------------------------+
| 0x11      | CPU 异常 NMI                                      |
+-----------+---------------------------------------------------+
| 0x12      | CPU 异常 MemManage                                |
+-----------+---------------------------------------------------+
| 0x13      | CPU 异常 HardFault                                |
+-----------+---------------------------------------------------+
| 0x14      | CPU 异常 BusFault                                 |
+-----------+---------------------------------------------------+
| 0x15      | CPU 异常 UsageFault                               |
+-----------+---------------------------------------------------+
| 0x16      | CPU 异常 SecurityFault                            |
+-----------+---------------------------------------------------+
| 0x21      | OTP 为空                                          |
+-----------+---------------------------------------------------+
| 0x22      | 公钥为空                                          |
+-----------+---------------------------------------------------+
| 0x23      | 跳转 BIN 校验失败                                 |
+-----------+---------------------------------------------------+
| 0x1xxx    | OTP 读失败                                        |
+-----------+---------------------------------------------------+
| 0x8yyyyyyy| 验签失败                                          |
+-----------+---------------------------------------------------+

其中 xxx 指 OTP 的 OFFSET，yyyyyyy 指具体的验签失败点。

严重错误在打印时仅打出错误码，如 "E16" 表示CPU 异常 SecurityFault。

.. note::

 当严重错误使能时，BL1 安全启动时并不会初始化 UART，仅当产生了不可恢复的严重错误时才会初始化 UART，进行打印。
 因此，严重错误并不会影响正常启动功能，也不会带来安全问题。

.. important::

  一般在开发阶段，尤其是尚未在任何板子上成功配置过安全启动之前，建议开启普通日志，这样，可以看到更多调试信息；
  在熟悉了安全启动配置之后，或者在量产阶段，应该关闭普通日志。严重错误则建议在量产版本中也不要关闭。

.. _efuse_bit2:

BIT(2) - fast boot disable
+++++++++++++++++++++++++++++++++++++++++++++++

BIT(2) 置 0 时使能 Fast Boot 启动，置 1 时关闭 Fast Boot 启动。

Fast Boot 用于控制系统从 Deep Sleep 醒来的流程，当 Fast Boot 使能时，Deep Sleep 醒来后跳过安全启动，直接跳转到应用程序中；
当 Fast Boot 关闭时，则与上电重启类似，会做完整的安全启动。

.. important::

  Fast Boot 使能时，启动速度更快，但不够安全；Fast Boot 关闭时，启动速度较慢，但安全可靠。
  应用应该依据实际需求决定是否开关 Fast Boot。

.. _efuse_bit3:

BIT(3) - download disable
+++++++++++++++++++++++++++++++++++++++++++++++

BIT(3) 用于禁用下载模式：

 - 0 - 下载模式使能，支持传统下载。
 - 1 - 下载模式禁用，禁止 UART 下载。

.. _efuse_bit4:

BIT(4) - security boot clock select
+++++++++++++++++++++++++++++++++++++++++++++++

BIT(4) 用于使能/关闭安全启动高频模式。

 - 0 表示 CPU 与 FLASH 使用 XTAL 作为时钟。
 - 1 表示使能 PLL，CPU 与 FLASH 配置在高频模式。

在高频模式下，安全启动速度更快，对启动性能有要求的应用一般建议使能高频模式。

.. _efuse_bit5:

BIT(5) - random delay enable
+++++++++++++++++++++++++++++++++++++++++++++++

BIT(5) 用于控制 BootROM 中关闭判断语句的随机延迟:

 - 0 表示随机延时关闭。
 - 1 表示开启。当随机延时开启时，BL1 在调用关键函数前，都会做一个随机 delay，通过这种机制减缓 :ref:`故障注入攻击<fault_injection_attack>` 带来的影响。

.. note::

 随机延时使能会增加安全启动时间，除非需要应对注入攻击防范特别高的应用场景，通常不建议打开随机延迟功能!

.. _efuse_bit6:

BIT(6) - bl1 power on fastboot
+++++++++++++++++++++++++++++++++++++++++++++++

BIT(6) 用于配置 BL1 在上电启动时是否跳过验签流程：

 - 0 表示允许跳过验签：仅当为上电重启 (power on restart) 且 FLASH 中的 bypass 标志满足跳过条件时，BL1 才跳过镜像验签，以加快启动。
 - 1 表示不跳过验签：任何安全启动场景下，BL1 都执行完整的验签流程。

.. _efuse_bit7:

BIT(7) - security boot critical error
+++++++++++++++++++++++++++++++++++++++++++++++

BIT(7) 用于控制安全启动过程中严重错误的打印：

 - 0 - 使能安全启动中严重错误打印。当发生不可恢复的严重错误时，BL1 会初始化 UART 并打印错误码。
 - 1 - 关闭安全启动中严重错误打印。

BIT(7) 与 :ref:`BIT(1)<efuse_bit1>` 配合使用，分别控制严重错误与普通调试信息。严重错误码含义请参考 BIT(1) 章节中的错误码表。

.. note::

 当严重错误打印使能时，BL1 在正常安全启动过程中并不会初始化 UART，仅当产生了不可恢复的严重错误时才会初始化 UART 进行打印。
 因此，严重错误打印并不会影响正常启动功能，也不会带来安全问题。

.. important::

  建议在量产版本中保持严重错误打印使能（BIT(7) 置 0），以便定位启动失败问题。

.. _efuse_bit27:

BIT(27) - flash crc mode
+++++++++++++++++++++++++++++++++++++++++++++++

BIT(27) 用于配置 FLASH 指令口访问时是否启用 CRC 校验：

 - 0 - CRC 模式。FLASH 控制器每 32 字节数据附加 2 字节 CRC，虚拟地址与物理地址存在映射关系。
 - 1 - 无 CRC 模式。虚拟地址与物理地址相同。

该位必须与固件打包时的 CRC 配置一致。打包工具根据 security.csv 或 auto_partitions.csv 中的 FLASH_CRC_ENABLE 生成镜像；:ref:`OTP EFUSE 配置<bk_config_otp_efuse>` 中对应字段为 flash_no_crc_enable（EFUSE 第 3 字节 BIT(3)）。详细说明请参考 :ref:`FLASH AES 加密与 CRC<bk_security_flash_aes_crc>`。

.. important::

  EFUSE 中的 CRC 配置必须与烧录到 FLASH 中的镜像格式一致，否则芯片无法正常启动。

.. _efuse_bit28:

BIT(28) - flash aes mode
+++++++++++++++++++++++++++++++++++++++++++++++

BIT(28) 用于选择 FLASH AES 加密算法模式，在 :ref:`BIT(29) flash aes enable<efuse_bit29>` 使能后生效：

 - 0 - FLASH AES-XTS-128 模式。AES KEY 长度为 32 字节。
 - 1 - 暂不支持。

该位必须与 OTP 中部署的 :ref:`FLASH AES KEY <otp_flash_aes_key>` 长度及打包配置一致。

.. _efuse_bit29:

BIT(29) - flash aes enable
+++++++++++++++++++++++++++++++++++++++++++++++

BIT(29) 用于使能 FLASH AES 加密：

 - 0 - FLASH AES 加密不使能。
 - 1 - FLASH AES 加密使能。此时必须配置 :ref:`FLASH AES KEY <otp_flash_aes_key>`。

.. _efuse_bit30:

BIT(30) - spi download disable
+++++++++++++++++++++++++++++++++++++++++++++++

关闭 SPI 下载功能:

 - 0 - 内部 SPI FLASH 通道使能，支持 SPI 下载。
 - 1 - 内部 SPI FLASH 通道关闭，不支持 SPI 下载。

需要注意，BIT(30) 与 :ref:`BIT(21) spi to ahb disable<efuse_bit21>` 相互独立，需要分别配置。

.. important::

  为避免带来安全隐患，量产版本中应该禁用 SPI 下载。但在尚未成功部署安全启动之前，可先不要禁用 SPI 下载，
  这样，当安全启动部署失败时，依然可通过 SPI 下载将版本下载到 FLASH。否则，一旦安全启动部署失败，就再
  也无法下载版本，板子变砖。

.. _efuse_bit31:

BIT(31) - SWD 调试
+++++++++++++++++++++++++++++++++++++++++++++++

BIT(31) 用于控制 CPU 调试口的开关:

 - 0 - CPU 调试开启，BK7236N 支持 SWD 调试。
 - 1 - CPU 调试关闭。此时，必须通过 :ref:`安全调试 <security_secure_debug>` 才能使能 CPU 调试功能。

.. important::

 安全启动使能时，需要关闭 SWD 调试。
