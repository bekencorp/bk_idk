======
SARADC
======

:link_to_translation:`en:[English]`

概述
======

BK7236N 集成了一颗 14 位 **SARADC**\ （Successive Approximation Analog-to-Digital Converter，逐次逼近型模数转换器），
支持单次（One-shot）和连续（Continuous）两种采样模式。

主要特性：

 - **分辨率**\ ：14 bit。
 - **可编程采样率**\ ：51.28 kHz ~ 1.538 MHz。
 - **最多 10 个外部模拟输入通道**\ ：ADC2 / ADC3 / ADC4 / ADC5 / ADC6 / ADC10 / ADC12 / ADC13 /
   ADC14 / ADC15。
 - **5 个内部专用通道**\ ：

   - ADC0：电池电压监测（VBAT/4）
   - ADC7：内部温度传感器（TEMP）
   - ADC8：TSSIO
   - ADC9 / ADC11：内部调试通道

 - **采样模式**\ ：

   - 单次（One-shot / Single-step）：每次只采集一个数据并停止，等待 MCU 读取。
   - 连续（Continuous）：硬件按设定的采样率持续采样，FIFO 计数达到阈值后产生中断。

 - **硬件 FIFO**\ ：内部 FIFO 缓存采样数据，连续模式下通过 FIFO 水位中断上报。
 - **逐 bit 权重校准（CWT）**\ ：通过 16 个 24-bit ``cwt_calXX`` 寄存器对 ADC 16 个 bit 各自的权重进行修正，再叠加增益 ``co_gain`` 和偏移 ``co_offset``，提高线性度与一致性。

+-------------------+---------+----------------------------------------------------+
| 字段              | Bit     | 说明                                               |
+===================+=========+====================================================+
| enable            | [0]     | ADC 使能（1：启动采样）                            |
+-------------------+---------+----------------------------------------------------+
| calib_mode        | [1]     | 校准模式：1 输出原始采样数据用于 LMS 校准          |
+-------------------+---------+----------------------------------------------------+
| calib_done        | [2]     | 软件校准完成标志：1 表示输出已校准的数据           |
+-------------------+---------+----------------------------------------------------+
| samp_sel          | [3]     | 采样时钟沿选择                                     |
+-------------------+---------+----------------------------------------------------+
| adc_chan          | [7:4]   | 通道选择（0~15，对应 ADC0~ADC15）                  |
+-------------------+---------+----------------------------------------------------+
| adc_mode          | [8]     | 工作模式（0：single；1：continuous）               |
+-------------------+---------+----------------------------------------------------+
| adc_dump_num      | [11:9]  | 启动时丢弃的前 N 个数据                            |
+-------------------+---------+----------------------------------------------------+
| adc_sclk_div      | [15:12] | 采样时钟分频系数 ``adc_clk = src / (div * 2)``     |
+-------------------+---------+----------------------------------------------------+
| adc_sraw          | [16]    | 正常模式下是否输出原始数据（0 输出校准后数据）     |
+-------------------+---------+----------------------------------------------------+

+-------------------+---------+----------------------------------------------------+

-------------------------------------------

+-------------------+----------+----------------------------------------------------+
| 字段              | 寄存器   | 说明                                               |
+===================+==========+====================================================+
| adc_int_en        | reg17[0] | 中断使能                                           |
+-------------------+----------+----------------------------------------------------+
| adc_int_level     | reg17    | FIFO 中断水位：FIFO 中数据数 > level 时触发中断    |
|                   | [6:1]    | （仅 continuous 模式有效；single 模式固定 2 个）   |
+-------------------+----------+----------------------------------------------------+
| fifo_rdata        | reg18    | FIFO 数据读出口（16 bit，每次读弹出一个数据）      |
+-------------------+----------+----------------------------------------------------+
| fifo_full         | reg19[0] | FIFO 满标志（只读）                                |
+-------------------+----------+----------------------------------------------------+
| fifo_empty        | reg19[1] | FIFO 空标志（只读，复位值为 1）                    |
+-------------------+----------+----------------------------------------------------+
| int_state         | reg19[2] | 中断状态标志（写 1 清零，RW1C）                    |
+-------------------+----------+----------------------------------------------------+

校准系数寄存器（reg5 / reg6 / reg7~reg16）
-------------------------------------------

ADC 输出由以下公式计算（``ADCout`` 为最终的 14 位采样值，``adci<k>`` 为第 k 位原始 SAR 比较结果）：

.. math::

    ADCout_{[13:0]} = \mathrm{Round}\Big( (co\_gain + 1) \times \sum_{k=0}^{15} adci_{<k>} \times reg\_cwt\_ini_{<k>}\;+\;co\_offset \Big)

- ``co_gain`` (reg5)：8 位增益修正
- ``co_offset`` (reg6)：16 位偏移修正
- ``cwt_cal00`` ~ ``cwt_cal0f`` (reg7~reg16)：16 个 24 位 bit 权重系数

软件可通过 LMS（Least Mean Squares，最小均方）算法在线计算这些系数，
详见后文 :ref:`saradc-calibration`\ 。

软件架构
==========

SARADC 软件分为以下 4 层：

.. list-table::
    :header-rows: 1
    :widths: 6 14 42 38

      - 代码位置
      - 职责

    * - 3

通道与 GPIO 映射
==================

ADC 通道分两类：

+--------------+---------------------------------+--------------------------------------------+
| 类别         | 通道                            | 说明                                       |
+==============+=================================+============================================+
| 内部专用通道 | ADC0                            | VBAT/4 电池电压监测                        |
+              +---------------------------------+--------------------------------------------+
|              | ADC7                            | 内部温度传感器（TEMP）                     |
+              +---------------------------------+--------------------------------------------+
|              | ADC8                            | TSSIO                                      |
+              +---------------------------------+--------------------------------------------+
|              | ADC9 / ADC11                    | 内部调试通道                               |
+--------------+---------------------------------+--------------------------------------------+
| 外部模拟通道 | ADC2 / 3 / 4 / 5 / 6            | 映射到 GPIO_3 ~ GPIO_7                     |
+              +---------------------------------+--------------------------------------------+
|              | ADC10                           | 映射到 GPIO_8                              |
+              +---------------------------------+--------------------------------------------+
|              | ADC12 / 13 / 14 / 15            | 映射到 GPIO_0 / GPIO_1 / GPIO_12 / GPIO_13 |
+--------------+---------------------------------+--------------------------------------------+

详细的通道 → GPIO 对应表见 ``middleware/soc/bk7236n/soc/adc_map.h`` 中的 ``ADC_DEV_MAP``：

.. code-block:: c

    /* ADC_DEV_MAP（节选） */
    {ADC_2,  GPIO_3,  GPIO_DEV_ADC2 },
    {ADC_3,  GPIO_4,  GPIO_DEV_ADC3 },
    ...
    {ADC_14, GPIO_12, GPIO_DEV_ADC14},
    {ADC_15, GPIO_13, GPIO_DEV_ADC15},

ADC 通道与 GPIO 的对应关系由 **硬件固定**，使用时不需要像 UART、SPI 等数字外设那样通过 IOMUX
配置功能码，把对应 GPIO 配置为普通 GPIO 模式即可。该工作由驱动在 ``bk_adc_channel_raw_read()`` /
``bk_adc_channel_read()`` 内部通过 ``adc_init_gpio()`` 自动完成，应用层无需介入。

.. note::

    SARADC 硬件同一时刻只能选中一个通道。驱动在 ``bk_adc_channel_raw_read()`` /
    ``bk_adc_channel_read()`` 内部自带互斥保护，多任务并发读取不同通道时也是安全的，
    应用层无需自行加锁。

工作模式
==========

BK7236N SARADC 硬件支持两种工作模式，由 ``reg4.adc_mode`` 这 1 bit 选择，对应 ``adc_mode_t``：

.. list-table::
    :header-rows: 1
    :widths: 35 65

    * - 模式
      - 说明
    * - ``ADC_SINGLE_STEP_MODE``
      - Single-step 模式：使能后采集 2 个数据进入 FIFO 即停止，等待 MCU 读取；下一次采样需重新使能。
    * - ``ADC_CONTINUOUS_MODE``
      - Continuous 模式：按 ``sample_rate`` 持续采样写入 FIFO，FIFO 数据数超过 ``adc_int_level`` 时触发中断。

.. note::

    ``adc_mode_t`` 中还存在 ``ADC_SLEEP_MODE`` 和 ``ADC_SOFTWARE_CONTRL_MODE`` 两个枚举值，
    它们是为了兼容老芯片而保留的定义，BK7236N 上传入这两个值会被驱动静默忽略，
    新代码中请勿使用，仅在上述 single-step / continuous 两种模式中选择。

时钟与采样率
==============

BK7236N SARADC 的时钟源 **硬件固定为 XTAL 40 MHz**，软件无法切换。 ``adc_src_clk_t`` 枚举中其它值（ ``ADC_SCLK_DCO`` / ``ADC_SCLK_32M`` / ``ADC_SCLK_DPLL``）是为兼容老芯片保留的，BK7236N 上均不可用。

软件能调整的只有 ``reg4[15:12]`` 这 4 bit 的 ``adc_sclk_div`` 分频系数，决定 ADC 采样时钟 ``adc_clk = 40 MHz / (adc_sclk_div × 2)``。 ``adc_sclk_div`` 取值 1 ~ 15 时， ``adc_clk`` 范围约为 **1.33 MHz ~ 20 MHz**。

推荐用法是把目标 ``adc_clk`` 填入 ``adc_config_t.clk``，连同其它字段一起传给 ``bk_adc_channel_init()``，驱动会自动计算分频值并写入硬件。下面是 RF 校准模块中真实的初始化代码（见 ``components/bk_phy/src/bk_phy_adapter.c``）：

.. code-block:: c

    adc_config_t config = {0};
    config.chan          = adc_channel;             /* 必填 */
    config.adc_mode      = ADC_CONTINUOUS_MODE;     /* 必填：单步 / 连续 */
    config.src_clk       = ADC_SCLK_XTAL;           /* 固定填 XTAL */
    config.clk           = 5 * 1000 * 1000;         /* adc_clk = 5 MHz, 即 sclk_div = 4 */
    /* 以下字段在 BK7236N 上不生效，保持默认 0 即可，此处保留是为了与老芯片配置代码兼容 */
    config.saturate_mode = ADC_SATURATE_MODE_3;
    config.sample_rate   = 0;
    config.steady_ctrl   = steady_time;
    config.adc_filter    = 0;

    bk_adc_channel_init(&config);

.. warning::

    驱动按 ``adc_sclk_div = 40MHz / (2 × config.clk)`` 计算后直接写 4 bit 位域，硬件 **取低 4 bit** 且不做范围检查、不报错。若 ``config.clk`` 低于 1.33 MHz， ``adc_sclk_div`` 会 ≥ 16 而被截断成错误值，导致实际 ``adc_clk`` 偏离预期。请确保 ``config.clk`` 落在 **1.33 MHz ~ 20 MHz** 范围内。

校准机制
==========

SARADC 的校准包含两个部分：

1. **CWT 系数校准（核心）**\ ：辨识 16 个 bit 权重，写入 ``cwt_cal00`` ~ ``cwt_cal0f`` 寄存器。
2. **增益 / 偏移修正**\ ：写入 ``co_gain`` (reg5) 和 ``co_offset`` (reg6)。

CWT 系数有两个来源，驱动在 ``bk_adc_driver_init()`` → ``bk_adc_enter_calib_mode()`` 中按 **OTP 优先、LMS 兜底** 的策略选择：

.. code-block:: text

    bk_adc_enter_calib_mode()                         # 仅 CONFIG_SARADC_V1P2
        ├── adc_try_load_otp_cwt()                    # 优先：从 OTP 加载
        │     └── 读 OTP_GADC_CALIBRATION (72 B)，校验末位非 0
        │
        ├── 若 OTP 加载成功 ───► adc_hal_set_cwt(otp_cwt)        # 直接写寄存器
        │                       (跳过 LMS，耗时极短)
        │
        └── 若 OTP 加载失败（空芯片 / 校验失败）
              ├── adc_hal_calib_init()               # 复位 + 模拟域上电
              ├── 采集 ADC_CALIBRATION_DATA_NUM 个原始数据
              │     (calib_mode=1, sraw=1, gain=0, offset=0)
              ├── adc_hal_set_cwt_calib(buf, n)      # 调 LMS 算法
              │     └── adc_cali_lms()               # 16 bit 权重迭代收敛
              └── 写回 cwt_cal00..0f, calib_done=1   # 耗时约几十毫秒

正常情况下，BK7236N 在 CP/FT 量产测试阶段已经完成 ADC 校准，并把 CWT 系数固化到 OTP 的 ``OTP_GADC_CALIBRATION`` 区（72 字节，含备份区 ``OTP_GADC_CALIBRATION_BACKUP``）。出厂芯片上电后 ``adc_try_load_otp_cwt()`` 会读到有效系数并直接生效，应用层无需感知。

只有 OTP 中没有有效校准值的"空芯片"（例如开发阶段的工程片，或 OTP 数据被破坏），驱动才会自动回退到 LMS 在线校准路径，单次校准耗时约几十毫秒。

数据通路
==========

驱动维护两层 buffer：

.. list-table::
    :header-rows: 1
    :widths: 22 78

    * - Buffer
      - 说明
    * - **Hardware FIFO**
      - 由 IP 内置，每次采样完成把 16 位 ADC 数据压入；通过 ``reg18.fifo_rdata`` 读取， ``reg19.fifo_full`` / ``reg19.fifo_empty`` 反映满 / 空状态。
    * - **Software Buffer**
      - 应用调用 ``bk_adc_channel_raw_read()`` 时传入的 ``uint16_t* buf`` 。ISR 在 FIFO 非空时把数据搬到该缓冲。

连续模式下的数据通路：

.. code-block:: text

    ADC HW   ──采样──>  HW FIFO
                          │ adc_int_level 触发
                          ▼
                       INT_SRC_SARADC
                          │
                          ▼
                  adc_isr() (Driver)
                          │
                          ├── 清中断状态
                          ├── while(!fifo_empty):
                          │      buf[i++] = fifo_rdata
                          ├── 当 i >= sampling_request:
                          │      adc_stop_conversion()
                          │      rtos_set_semaphore(sync)
                          └── 调用用户注册的 isr_cb（如有）

应用线程通过 ``rtos_get_semaphore(&dev->ctx.sync, timeout)`` 等待采样完成。

中断处理
==========

ADC 中断源为 ``INT_SRC_SARADC``。驱动在 ``bk_adc_driver_init()`` 中注册统一 ISR
``adc_isr()``，按以下步骤处理：

1. ``adc_hal_clear_int_status()`` 写 ``int_state = 1`` 清中断标志。
2. 循环读取 FIFO 直到 ``fifo_empty = 1``，把数据写入软件 buffer。
3. 数据填满后停止转换并释放信号量。
4. 调用用户通过 ``bk_adc_register_isr_callback()`` 注册的回调（可选）。

应用通过两种方式获取数据：

 - **同步**\ ：调用 ``bk_adc_channel_read()`` / ``bk_adc_channel_raw_read()``，驱动内部等待信号量。
 - **异步**\ ：注册 ``adc_isr_t`` 回调，每次中断到来时由驱动直接转发。

低功耗管理
============

SARADC 挂在 **APB-BAKP** 电源域下，并以 ``PM_DEV_ID_SARADC`` 注册到低功耗子系统。关键回调与电源投票：

 - ``bk_pm_module_vote_power_ctrl(PM_POWER_SUB_MODULE_NAME_BAKP_SADC, ON)``：在 ``bk_adc_channel_init()`` 中投票打开 APB-BAKP 域里的 SADC 子模块电源。
 - ``adc_pm_restore_cb()``：仅在 ``PM_MODE_LOW_VOLTAGE`` 唤醒后被调用，内部走 ``hal_calib_apply()`` 完成 ADC 软复位、reg4 基线写入、CWT 系数回写、关中断等动作，使 ADC 重新具备工作条件。
 - 若未启用 ``CONFIG_SARADC_PM_CB_SUPPORT``，唤醒后需要应用自己重新调用 ``bk_adc_driver_init()`` 与 ``bk_adc_channel_init()``。

.. note::

    **Low-Voltage 模式**\ ：为了进一步降低功耗，APB-BAKP 电源域会被关闭，挂在该域下的 SARADC 数字寄存器随之全部清空。唤醒后：

     - **CWT 校准系数**\ ：驱动通过 ``adc_pm_restore_cb()`` → ``hal_calib_apply()`` 自动把 RAM 中缓存的系数重新写回硬件。
     - **应用层配置**\ （``chan`` / ``adc_mode`` / ``clk`` 等）：不在 PM 回调里恢复，而是在下一次 ``bk_adc_channel_raw_read()`` / ``bk_adc_channel_read()`` 内部由 ``adc_activate_config()`` 自动重写一次。

    因此 LV 唤醒后应用层无需做任何额外初始化。

    **Deep-Sleep 模式**\ ：整个 SARADC（含模拟部分）完全掉电，唤醒后等同于软重启，必须重新调用 ``bk_adc_driver_init()`` 与 ``bk_adc_channel_init()``。

API 使用示例
==============

``adc_config_t`` 字段说明
--------------------------

.. note::

    ``adc_config_t`` 中真正会影响 BK7236N 硬件行为的只有 4 个字段： ``chan`` 、 ``adc_mode`` 、
    ``src_clk`` （仅能填 ``ADC_SCLK_XTAL`` ）、 ``clk`` 。其余字段在 BK7236N 上 **驱动直接忽略**，
    HAL 层为空宏 / 空函数，不写任何寄存器，仅为兼容老芯片配置代码而保留：

    +------------------------------+--------------------------------------------------------------+
    | 字段                         | 在 BK7236N 上的实际效果                                      |
    +==============================+==============================================================+
    | ``sample_rate``              | ``adc_hal_set_sample_rate`` 为空宏                           |
    +------------------------------+--------------------------------------------------------------+
    | ``adc_filter``               | ``adc_hal_set_adc_filter`` 为空宏                            |
    +------------------------------+--------------------------------------------------------------+
    | ``steady_ctrl``              | ``adc_hal_set_steady_ctrl`` 为空宏                           |
    +------------------------------+--------------------------------------------------------------+
    | ``saturate_mode``            | ``adc_hal_set_saturate_mode`` 为空函数                       |
    +------------------------------+--------------------------------------------------------------+
    | ``vol_div``                  | ``adc_hal_set_vol_div`` 为空函数                             |
    +------------------------------+--------------------------------------------------------------+
    | ``is_hw_using_cali_result``  | 分支调用的 ``adc_hal_enable/disable_bypass_calib`` 为空宏    |
    +------------------------------+--------------------------------------------------------------+

    此外， ``adc_dump_num`` （启动时丢弃的样本数）由驱动在 ``adc_hal_init()`` 中硬编码为 5，
    既不需要、也不能由应用层配置。

连续模式采集示例
-----------------

下面给出连续模式下采集 32 个原始数据的典型流程：

.. code-block:: c

    #include <driver/adc.h>

    #define ADC_SAMPLE_NUM   32

    void adc_continuous_example(void)
    {
        uint16_t buf[ADC_SAMPLE_NUM] = {0};

        /* 1. 初始化 ADC 驱动（CWT 校准在内部完成） */
        bk_adc_driver_init();

        /* 2. 配置通道 ADC_3（GPIO_4） */
        adc_config_t cfg = {
            /* 必填字段 */
            .chan         = ADC_3,
            .adc_mode     = ADC_CONTINUOUS_MODE,
            .src_clk      = ADC_SCLK_XTAL,
            .clk          = 5 * 1000 * 1000,   /* adc_clk = 5 MHz */
            /* 以下字段在 BK7236N 上不生效，详见上文字段说明，保持默认 0 即可 */
            .sample_rate  = 0,
            .adc_filter   = 0,
            .steady_ctrl  = 0,
            .saturate_mode = 0,
            .vol_div      = 0,
            .is_hw_using_cali_result = 0,
        };
        bk_adc_channel_init(&cfg);

        /* 3. 一次同步采集（驱动内部启动 + 等中断 + 停止） */
        /*    第 3 个参数为采样点数（uint16_t 个数），不是字节数 */
        bk_adc_channel_raw_read(ADC_3, buf, ADC_SAMPLE_NUM, BEKEN_WAIT_FOREVER);

        /* 4. 退出 */
        bk_adc_channel_deinit(ADC_3);
    }

单次模式仅需把 ``adc_mode`` 改为 ``ADC_SINGLE_STEP_MODE`` 即可，读取调用 ``bk_adc_single_read(&data)``。

读取均值（驱动内部丢弃前半段数据，后半段求平均）：

.. code-block:: c

    uint16_t avg = 0;
    bk_adc_channel_read(ADC_3, &avg, BEKEN_WAIT_FOREVER);

将原始 ADC 码值转为电压（mv）：

.. code-block:: c

    float voltage_mv = bk_adc_data_calculate(adc_val, ADC_3);

注意事项
==========

1. **使用前必须先调用驱动初始化**\ ：``bk_adc_driver_init()`` 内部会加载 CWT 校准系数（详见 :ref:`saradc-calibration`）；如果跳过，后续所有采样数据将偏离真实电压。

2. **同一时刻只能选中一个通道**\ ：``adc_chan`` 字段在 ``reg4`` 中是 4 bit。驱动在 ``bk_adc_channel_raw_read()`` / ``bk_adc_channel_read()`` 内部已自带互斥保护，多任务并发读取不同通道是安全的，应用层无需额外加锁。

3. **不要在 ADC 引脚上启用其它 GPIO 功能**\ ：驱动会在采样时自动把对应 GPIO 设为不主动驱动的普通 GPIO；应用切勿在采样过程中再去对该 GPIO 启用上下拉、输入或输出。

4. **校准数据的来源**\ ：BK7236N 出厂时 CP/FT 已完成 ADC 校准并把 CWT 系数固化到 ``OTP_GADC_CALIBRATION``；驱动初始化时优先读 OTP，OTP 无效（空芯片）才会回退到 LMS 在线校准。

5. **时钟源固定为 XTAL 40 MHz**\ ：BK7236N 上 ADC 时钟源不可切换，应用层只需在 ``adc_config_t.clk`` 中指定期望的 ``adc_clk`` 频率（1.33 MHz ~ 20 MHz）， ``adc_config_t.src_clk`` 固定填 ``ADC_SCLK_XTAL`` 即可。
