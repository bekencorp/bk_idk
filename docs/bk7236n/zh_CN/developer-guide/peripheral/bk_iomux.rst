======
IOMUX
======

:link_to_translation:`en:[English]`

概述
======

IOMUX（IO Multiplexer，IO 复用器），又称 IO Matrix，是 BK7236N 芯片中负责管理 GPIO 引脚功能复用的硬件模块。

BK7236N 共有 **24 个 GPIO**\ （GPIO_0 ~ GPIO_23），每个 GPIO 通过 IOMUX 可以被配置为通用 IO，或映射为外设功能
（如 UART、SPI、I2C、I2S、PWM、SDIO、QSPI 等）。

IOMUX 为每个 I/O 引脚提供一组独立的配置寄存器，其中最核心的字段为 ``GPIOx_FUNC_SEL[6:0]``：

 - ``FUNC_SEL = 0 ~ 3``：I/O 作为 GPIO 使用，分别对应 **高阻（High-Z）/ 输入 / 输出 / 输入输出** 四种模式。
 - ``FUNC_SEL = 4 ~ 94``：I/O 连接到某个外设功能（全交叉矩阵，任意 GPIO 可选任意功能）。
 - ``FUNC_SEL = 95 ~ 127``：保留，等价于高阻状态。

BK7236N 的 IOMUX 模块具备以下主要能力：

 - **功能复用**：7 位功能码字段（0~127），共计 95 个有效功能。
 - **方向控制**：高阻、输入、输出、输入输出四种模式。
 - **Push-pull 输出**：支持推挽式输出。
 - **内部上下拉**：独立的上拉/下拉使能与方向选择。
 - **驱动能力**：4 级可调驱动能力（0~3）。
 - **中断生成**：支持电平触发与边沿触发（高/低电平，上升/下降沿）。
 - **汇总寄存器**：提供全局寄存器一次性查询所有 GPIO 的中断状态、输入电平，或一次性配置输出电平。
 - **低功耗管理**：GPIO 状态备份/恢复，支持作为唤醒源。

.. important::

    硬件约束：**同一个外设功能不能同时映射到多个 GPIO**。如果多个 GPIO 的 ``FUNC_SEL`` 设置为同一个外设功能码，
    信号将冲突，行为未定义。应用程序在分配引脚时必须保证每个外设功能只被一个 GPIO 使用。

硬件架构
==========

寄存器布局
-----------

IOMUX 模块的寄存器组由以下几类寄存器组成（详见 ``middleware/soc/bk7236n/soc/iomx_struct.h``）：

+-------------------------+----------------------------------------------------------+
| 寄存器                  | 功能                                                     |
+=========================+==========================================================+
| ``dev_id``              | 设备 ID（只读）                                          |
+-------------------------+----------------------------------------------------------+
| ``ver_id``              | 版本 ID（只读）                                          |
+-------------------------+----------------------------------------------------------+
| ``clkg_reset``          | 时钟门控与软复位控制                                     |
+-------------------------+----------------------------------------------------------+
| ``dev_status``          | 设备状态（只读）                                         |
+-------------------------+----------------------------------------------------------+
| ``gpio_cfg[N]``         | 每个 GPIO 独立的配置寄存器（核心配置寄存器）             |
+-------------------------+----------------------------------------------------------+
| ``gpio_intsta``         | 所有 GPIO 的中断状态汇总                                 |
+-------------------------+----------------------------------------------------------+
| ``gpio_input``          | 所有 GPIO 的输入电平汇总                                 |
+-------------------------+----------------------------------------------------------+
| ``gpio_output``         | 所有 GPIO 的输出电平汇总                                 |
+-------------------------+----------------------------------------------------------+
| ``gpio_func_*_atpg``    | ATPG 测试相关寄存器                                      |
+-------------------------+----------------------------------------------------------+

其中最核心的是 ``gpio_cfg`` 数组，BK7236N 的每个 GPIO 都有一个独立的 32 位配置寄存器。

GPIO 配置寄存器字段
---------------------

每个 GPIO 的 ``gpio_cfg`` 寄存器字段定义如下：

+-------------------+---------+----------------------------------------------------+
| 字段              | Bit     | 说明                                               |
+===================+=========+====================================================+
| gpio_input        | [0]     | 输入使能                                           |
+-------------------+---------+----------------------------------------------------+
| gpio_output       | [1]     | 输出使能                                           |
+-------------------+---------+----------------------------------------------------+
| gpio_pull_mode    | [4]     | 上下拉方向（0: 下拉，1: 上拉）                     |
+-------------------+---------+----------------------------------------------------+
| gpio_pull_ena     | [5]     | 上下拉使能                                         |
+-------------------+---------+----------------------------------------------------+
| input_monitor     | [7]     | 输入监控使能                                       |
+-------------------+---------+----------------------------------------------------+
| gpio_capacity     | [8:9]   | 驱动能力（4 级：0~3）                              |
+-------------------+---------+----------------------------------------------------+
| gpio_int_type     | [10:11] | 中断类型（低电平/高电平/上升沿/下降沿）            |
+-------------------+---------+----------------------------------------------------+
| gpio_int_ena      | [12]    | 中断使能                                           |
+-------------------+---------+----------------------------------------------------+
| gpio_int_clear    | [13]    | 中断清除                                           |
+-------------------+---------+----------------------------------------------------+
| gpio_state        | [16:20] | 当前状态                                           |
+-------------------+---------+----------------------------------------------------+
| gpio_func_sel     | [24:30] | 功能选择码 ``FUNC_SEL[6:0]``                       |
+-------------------+---------+----------------------------------------------------+

.. note::

    ``gpio_func_sel`` 硬件上为 7 位字段（``FUNC_SEL[6:0]``），取值范围 0~127，是选择 GPIO 所连接
    外设功能的关键字段。该字段的取值由 ``IOMX_CODE_T`` 枚举定义（见
    ``include/driver/hal/hal_io_matrix_types.h``），包括 ``FUNC_CODE_HIGH_Z``、``FUNC_CODE_INPUT``、
    ``FUNC_CODE_OUTPUT``、``FUNC_CODE_UART0_TXD`` 等。

.. note::

    IOMUX 除了每个 GPIO 的独立配置寄存器，还提供了若干 **全局汇总寄存器**：

     - ``gpio_intsta``：一次性读取所有 GPIO 的中断状态（24 位汇总）。
     - ``gpio_input``：一次性读取所有 GPIO 的输入电平。
     - ``gpio_output``：一次性配置所有 GPIO 的输出电平。

    这些寄存器在 GPIO 扫描、按键矩阵、并行数据采集等场景下可以显著提升性能。

软件架构
==========

IOMUX 子系统在软件上分为 4 层（适配层 / Driver / HAL / LL），对上承接应用层 API，对下直达硬件寄存器：

.. list-table::
    :header-rows: 1
    :widths: 8 18 32 42

    * - 层级
      - 名称
      - 代码位置
      - 职责
    * - 1
      - 应用层 API
      - ``include/driver/gpio.h``
      - 暴露给用户的 ``bk_gpio_xxx()`` 接口，保持向后兼容。
    * - 2
      - GPIO 适配层
      - ``middleware/driver/io_matrix/v2.0/gpio_adapter.c``
      - 将 ``bk_gpio_*`` 映射到 ``bk_iomx_*``；提供 ``gpio_dev_t`` → ``IOMX_CODE_T`` 的转换（``contert_gpio_dev_to_iomx_code``），兼容旧版 GPIO 驱动接口。
    * - 3
      - Driver 层
      - ``middleware/driver/io_matrix/v2.0/io_matrix_driver.c``
      - 提供 ``bk_iomx_*`` 系列 API（如 ``bk_iomx_driver_init``、``bk_iomx_set_gpio_func``）；负责参数检查、中断注册、ISR 分发、低功耗备份与恢复。
    * - 4
      - HAL 层
      - ``middleware/soc/common/hal/iomx_hal.c``
      - 封装 LL 寄存器操作，提供面向 GPIO 编号的接口。典型 API：``iomx_hal_set_func_code()``、``iomx_hal_set_int_type()``、``iomx_hal_bakup_configs()``。
    * - 5
      - LL 层
      - ``middleware/soc/bk7236n/hal/iomx_ll.h``
      - ``inline`` 读写 IOMUX 寄存器位域，提供原子级别的寄存器访问。**该文件由脚本自动生成，禁止手动修改**。
    * - 6
      - 硬件寄存器
      - ``middleware/soc/bk7236n/soc/iomx_struct.h``
      - IOMUX 硬件寄存器结构体定义。

调用方向：**应用层 → 适配层 → Driver 层 → HAL 层 → LL 层 → 硬件寄存器**，上层依次调用下层。

初始化流程
============

GPIO 子系统通过 ``bk_gpio_driver_init()`` 完成初始化，内部调用 ``bk_iomx_driver_init()``：

.. code-block:: text

    bk_gpio_driver_init()
        ├── bk_iomx_driver_init()
        │     ├── iomx_hal_init()                  # 软复位 IOMUX，使能 GPIO 时钟
        │     ├── bk_int_isr_register(INT_SRC_GPIO, iomx_gpio_isr)
        │     └── sys_drv_int_group2_enable(GPIO_INTERRUPT_CTRL_BIT)
        ├── gpio_keep_status_init()                # 低功耗保持状态初始化
        ├── gpio_record_wakeup_pin_id()            # 记录唤醒源 GPIO
        └── gpio_dynamic_wakeup_source_init()      # 动态唤醒源初始化

.. note::

    初始化完成后，所有 GPIO 默认处于高阻（High-Z）状态，不会占用任何外设功能。
    应用程序需要按需调用 ``bk_gpio_set_config()`` 或 ``bk_iomx_set_gpio_func()`` 手动配置引脚。

.. note::

    BK7236N 不启用 ``CONFIG_GPIO_DEFAULT_SET_SUPPORT`` 配置项，因此 ``gpio_map.h`` 中的
    ``GPIO_DEFAULT_DEV_CONFIG``、``GPIO_DEV_MAP`` 等静态映射表 **不会参与默认初始化**，
    仅作为历史兼容残留。芯片启动后每个 GPIO 均以寄存器复位值为准，应用程序通过 API 自由配置。

功能复用机制
==============

与传统的"固定映射"架构不同，BK7236N 的 IOMUX 采用 **全交叉矩阵（full crossbar）** 设计：

 - 每个 GPIO 都有独立的 ``FUNC_SEL[6:0]`` 字段（7 位），可以任意选择 0~127 中的任何功能码。
 - **任意外设功能可以映射到任意 GPIO**，不存在固定的复用组。
 - PCB 布线、外设引脚分配具有极大的灵活性。

功能码按范围划分如下：

+-----------+-------------------+----------------------------------------+
| FUNC_SEL  | 类型              | 说明                                   |
+===========+===================+========================================+
| 0         | GPIO              | 高阻（High-Z）                         |
+-----------+-------------------+----------------------------------------+
| 1         | GPIO              | 输入                                   |
+-----------+-------------------+----------------------------------------+
| 2         | GPIO              | 输出                                   |
+-----------+-------------------+----------------------------------------+
| 3         | GPIO              | 输入输出                               |
+-----------+-------------------+----------------------------------------+
| 4 ~ 94    | 外设 I/O          | 连接到具体外设（UART/SPI/PWM 等）      |
+-----------+-------------------+----------------------------------------+
| 95 ~ 127  | 保留              | 等价于高阻                             |
+-----------+-------------------+----------------------------------------+

例如，要把 UART0_TXD 接到 GPIO_5，只需调用：

.. code-block:: c

    bk_iomx_set_gpio_func(GPIO_5, FUNC_CODE_UART0_TXD);

底层等价于写 ``gpio_cfg[5].gpio_func_sel = FUNC_CODE_UART0_TXD``。

.. important::

    **同一个外设功能不能同时分配给多个 GPIO**。例如不能同时设置 GPIO_5 和 GPIO_10 都为
    ``FUNC_CODE_UART0_TXD``，否则信号会冲突，行为未定义。切换外设引脚前，应先将旧 GPIO
    设置为 ``FUNC_CODE_HIGH_Z``，再配置新 GPIO。

.. note::

    虽然硬件支持任意 GPIO 选任意功能，但在实际应用中仍应参考硬件手册：某些高速信号
    （如 QSPI、SDIO、I2S）对 PCB 走线阻抗、长度匹配有要求，优先选择手册推荐的引脚。

切换引脚功能时，内部执行流程如下：

.. code-block:: text

    bk_gpio_enable_output(gpio_id)
        └── bk_iomx_set_gpio_func(gpio_id, FUNC_CODE_OUTPUT)
              └── iomx_hal_set_func_code(gpio_id, FUNC_CODE_OUTPUT)
                    └── iomx_ll_set_gpio_function_sel(FUNC_CODE_OUTPUT, gpio_id)
                          └── 写 gpio_cfg[gpio_id].gpio_func_sel = FUNC_CODE_OUTPUT

中断处理
==========

IOMUX 模块的 24 个 GPIO 共享一个中断向量（``INT_SRC_GPIO``）。中断处理流程如下：

.. code-block:: text

    GPIO 硬件中断
        └── iomx_gpio_isr()                        # Driver 层统一 ISR
              ├── iomx_hal_get_interrupt_status()  # 读取 gpio_intsta
              ├── 遍历 24 个 GPIO
              │    ├── 判断哪个 GPIO 触发
              │    ├── 调用对应 gpio_id 注册的 isr
              │    └── bk_iomx_clear_interrupt()   # 清除中断状态
              └── return

用户通过 ``bk_gpio_register_isr(gpio_id, isr)`` 注册回调，内部记录到 ``s_iomx_gpio_isr[]`` 数组中。
中断类型通过 ``bk_gpio_set_interrupt_type()`` 配置为以下四种之一：

 - ``GPIO_INT_TYPE_LOW_LEVEL``
 - ``GPIO_INT_TYPE_HIGH_LEVEL``
 - ``GPIO_INT_TYPE_RISING_EDGE``
 - ``GPIO_INT_TYPE_FALLING_EDGE``

.. note::

    在调用 ``bk_iomx_enable_interrupt()`` 使能中断之前，驱动会插入一个短暂延时循环（约 1000 个空循环），
    以等待芯片内部信号稳定，避免误触发中断。

低功耗管理
============

进入低功耗前的 GPIO 配置备份/恢复
------------------------------------

进入低功耗模式时，为了确保退出后 GPIO 状态一致，驱动会自动执行以下步骤（见 ``gpio_enter_low_power()``）：

1. ``iomx_backup_gpio_configs()`` 将所有 GPIO 的 ``gpio_cfg`` 寄存器保存到 RAM 中。
2. ``iomx_disable_all_interrupts()`` 关闭所有 GPIO 中断，避免低功耗期间误触发。
3. 配置保持状态 GPIO（``gpio_keep_status_config``）。
4. 配置唤醒源 GPIO（``gpio_wakeup_source_config``）。
5. 非唤醒、非保持状态的 GPIO 切换至高阻状态以降低漏电。

退出低功耗时执行 ``gpio_exit_low_power()``：

1. ``iomx_restore_gpio_configs()`` 从 RAM 恢复所有 GPIO 配置寄存器。
2. 清除由 ANA GPIO 产生的唤醒源状态。

.. note::

    Low Voltage 模式退出后 GPIO 状态自动恢复；Deep Sleep 模式退出等同于软重启，GPIO 状态不会自动恢复。

唤醒源配置
-----------

有两种配置 GPIO 唤醒源的方式：

1. **静态配置**：在 ``gpio_map.h`` 的 ``GPIO_STATIC_WAKEUP_SOURCE_MAP`` 表中声明。
2. **动态配置**：运行时调用 ``bk_gpio_register_wakeup_source()`` 相关 API。

唤醒源的中断类型应设置为边沿触发（``GPIO_INT_TYPE_RISING_EDGE`` 或 ``GPIO_INT_TYPE_FALLING_EDGE``），
且 ``low_power_io_ctrl`` 应配置为 ``GPIO_LOW_POWER_KEEP_INPUT_STATUS``。

API 使用示例
==============

典型的 GPIO 使用流程如下：

.. code-block:: c

    #include <driver/gpio.h>

    void gpio_example(void)
    {
        /* 1. Initialize GPIO driver */
        bk_gpio_driver_init();

        /* 2. Configure GPIO_10 as input with pull-up */
        gpio_config_t cfg = {
            .io_mode   = GPIO_INPUT_ENABLE,
            .pull_mode = GPIO_PULL_UP_EN,
        };
        bk_gpio_set_config(GPIO_10, &cfg);

        /* 3. Register interrupt on falling edge */
        bk_gpio_register_isr(GPIO_10, my_gpio_isr);
        bk_gpio_set_interrupt_type(GPIO_10, GPIO_INT_TYPE_FALLING_EDGE);
        bk_gpio_enable_interrupt(GPIO_10);

        /* 4. Use GPIO_11 as output */
        bk_gpio_enable_output(GPIO_11);
        bk_gpio_set_output_high(GPIO_11);
    }

    static void my_gpio_isr(gpio_id_t id)
    {
        /* handle the interrupt */
    }

注意事项
==========

1. 同一个 GPIO 只能同时映射到一个外设功能，上层驱动配置外设前应检查 GPIO 是否已被占用，
   若 ``bk_gpio_set_config()`` 返回 ``GPIO_ERR_INTERNAL_USED``，表示该 GPIO 正被其他外设使用。

2. 切换 GPIO 功能时建议先调用 ``bk_iomx_set_value(id, 0)`` 将寄存器清零，再设置新功能，
   避免残留配置干扰新功能。

3. 驱动能力（``GPIO_DRIVER_CAPACITY_0`` ~ ``GPIO_DRIVER_CAPACITY_3``）应根据负载电流实际需求配置，
   驱动能力越高功耗越大。I2C 等需要较强驱动的总线建议配置为 ``GPIO_DRIVER_CAPACITY_3``。

4. 在使能某个 GPIO 中断之前，应先调用 ``bk_gpio_register_isr()`` 注册回调函数，否则中断触发时回调为 NULL，
   仅清中断状态而无业务处理。

5. 低功耗状态下，未显式配置为唤醒源或保持状态的 GPIO 会被自动切换到高阻态，以减少漏电。
